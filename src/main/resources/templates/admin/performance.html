🎯 Conclusioni e Scelte Implementative

La strategia LAZY di default causa il problema N+1 query: per ogni articolo vengono generate query separate per caricare il venditore e le foto. Con N articoli il numero di query è circa 1 + 2N, rendendo la vetrina molto lenta al crescere dei dati.

Le strategie JOIN FETCH (JPQL) e @EntityGraph risolvono il problema eseguendo tutto in una singola query SQL con LEFT JOIN. L'EntityGraph è preferito perché è dichiarativo e non richiede JPQL manuale, mantenendo il repository pulito.

Scelta adottata in produzione: @EntityGraph(attributePaths = {"venditore", "fotoUrls"}) su ArticoloRepository.findAllByOrderByIdDesc() — usata nella vetrina principale di R3Play.
